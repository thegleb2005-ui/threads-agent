# Threads Content Agent

Telegram-бот + фоновый воркер, который превращает ссылку на YouTube-видео
в оригинальный черновик поста. **Публикация в Threads пока ручная** — бот
готовит текст, ты сам копируешь его и постишь.

## Как это работает

```
Ты кидаешь ссылку в Telegram
        │
        ▼
   очередь (SQLite)
        │
        ▼
  worker.py (фоновый цикл):
   1. downloader.py   — скачивает аудио (yt-dlp)
   2. transcriber.py  — распознаёт речь (по умолчанию локально, Whisper через faster-whisper)
   3. generator.py    — пишет ОРИГИНАЛЬНЫЙ пост по мотивам идеи (kie.ai)
        │
        ▼
  Черновик прилетает тебе в Telegram с кнопками:
  ✅ Готово   ✏️ Редактировать   🗑 Удалить
        │
        ▼
  Ты копируешь текст и публикуешь в Threads вручную
```

## Структура файлов

| Файл              | Что делает                                              |
|-------------------|----------------------------------------------------------|
| `bot.py`           | Точка входа. Telegram-интерфейс: команды, кнопки          |
| `worker.py`        | Фоновый цикл обработки очереди                             |
| `downloader.py`    | Скачивание аудио из YouTube                                |
| `transcriber.py`   | Распознавание речи (по умолчанию — локальный Whisper)      |
| `generator.py`     | Генерация текста поста (kie.ai)                             |
| `db.py`            | Очередь на SQLite                                           |
| `config.py`        | Загрузка настроек из `config.env`                                 |
| `config.env.example`     | Шаблон переменных окружения — скопируй в `config.env` и заполни   |
| `Dockerfile`       | Для деплоя на Bothost — ставит ffmpeg + Python-зависимости   |
| `threads_api.py`   | ⏸ Не используется сейчас. Публикация в Threads — готова, но не подключена (см. ниже) |
| `scheduler.py`     | ⏸ Не используется сейчас. Автопубликация по расписанию — готова, но не подключена  |
| `scripts/get_threads_token.py` | ⏸ Понадобится только когда включишь автопубликацию |
| `scripts/refresh_threads_token.py` | ⏸ Понадобится только когда включишь автопубликацию |

## 1. Требования

- Python 3.11+
- **ffmpeg НЕ нужно ставить отдельно** — идёт через `pip install -r requirements.txt`
  (пакет `imageio-ffmpeg` включает готовый бинарник). Работает одинаково
  что локально на Mac, что на любом хостинге, без прав на `apt install`.

## 2. Получение токенов

Для текущей (ручной) версии нужны только два сервиса — Threads API пока
не трогаем.

### Telegram
1. Напиши [@BotFather](https://t.me/BotFather) → `/newbot` → получишь `TELEGRAM_BOT_TOKEN`.
2. Напиши [@userinfobot](https://t.me/userinfobot) → получишь свой числовой `ADMIN_USER_ID`.

### Транскрибация — теперь по умолчанию локально, без ключей
`TRANSCRIBE_PROVIDER=local` (значение по умолчанию) — Whisper работает
прямо на сервере через `faster-whisper`, без единого сетевого запроса.
Ничего получать/настраивать не нужно — модель весов (~150 МБ для `base`)
скачается автоматически при первом обработанном видео и закешируется на
диске. Единственное, что стоит знать:

- Требует какого-то количества CPU/RAM на сервере — на большинстве
  обычных VPS-планов (от ~1 ГБ RAM) работает нормально. Если Bothost
  начнёт падать по памяти именно на этом шаге — попробуй уменьшить
  `WHISPER_MODEL_SIZE` до `tiny` (быстрее и легче, но грубее по качеству).
- При каждом переразвёртывании (redeploy) на Bothost, если файловая
  система контейнера не персистентная, модель может перекачиваться заново
  — это разовая задержка в несколько секунд-минут при первом видео после
  деплоя, не проблема, но заметно в логах.

### kie.ai (только генерация текста поста)
Используй тот же ключ и модель `gpt-5-2`, что уже настроены у тебя в
pptx-bot. Пропиши `KIE_API_KEY` в `config.env`.

Модели `elevenlabs` и `gemini` для транскрибации через kie.ai остались в
коде как переключаемые запасные варианты (`TRANSCRIBE_PROVIDER=elevenlabs`
или `=gemini`), но на практике оказались не очень надёжными — плохо
документированы и склонны таймаутить/менять формат ответа без
предупреждения. Используй только если `local` по какой-то причине не
подходит (например, совсем слабый тариф хостинга без запаса по памяти).

## 3. Настройка проекта

```bash
cd threads-agent
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt

cp config.env.example config.env
nano config.env   # заполни TELEGRAM_BOT_TOKEN, ADMIN_USER_ID, KIE_API_KEY
```

Поля `THREADS_USER_ID` / `THREADS_ACCESS_TOKEN` можно оставить пустыми —
они не нужны для запуска, бот не проверяет их наличие.

## 4. Локальный тест

```bash
python bot.py
```

В логах должно появиться `Бот запущен, жду сообщений...`. Напиши боту в
Telegram `/start`, потом кинь ссылку на короткое (5-10 минут) YouTube-видео
по теме мышления — и проверь, что через минуту-другую прилетает черновик.

## 5. Деплой на Bothost.ru

Хорошая новость: ffmpeg теперь ставится через pip (пакет `imageio-ffmpeg`
со встроенным бинарником), поэтому никаких системных пакетов и выбора
между "Python" и "Docker" не требуется — подходит обычный, самый простой
вариант деплоя, тот же, что уже настроен для pptx-bot.

1. Залей код в отдельный репозиторий на GitHub (уже сделали — `threads-agent`).
2. В панели Bothost.ru → **Создать новый проект**:
   - **Название**: `threads-agent` (или как удобно)
   - **Платформа**: Python
   - **Git URL**: `https://github.com/thegleb2005-ui/threads-agent.git`
   - **Bot Token**: сюда — значение `TELEGRAM_BOT_TOKEN`
   - **Описание**: любое, например "Агент для постов в Threads"
3. В разделе переменных окружения проекта добавь: `ADMIN_USER_ID`,
   `KIE_API_KEY`, `KIE_BASE_URL`, `KIE_MODEL`. `THREADS_*` можно оставить
   пустыми — сейчас не используются.
4. Сохрани и запусти проект.
5. Процесс должен быть **долгоживущим** (worker), не разовым заданием —
   бот держит постоянное соединение с Telegram (`start_polling`).

В проекте остался `Dockerfile` на случай, если когда-нибудь понадобится
переехать на хостинг, где обязателен явный Docker-образ — для Bothost он
не нужен.

## 6. Как пользоваться

- Кидаешь боту ссылку на YouTube-видео → бот отвечает "добавлено в очередь".
- `/queue` — что сейчас в обработке.
- Когда черновик готов, бот сам присылает его с кнопками:
  - **✅ Готово** — помечает пост завершённым в базе, текст выше просто копируешь и публикуешь сам.
  - **✏️ Редактировать** — пришли новый текст ответным сообщением, черновик обновится.
  - **🗑 Удалить** — черновик уходит в архив.
- `/pending` — показать все черновики, ожидающие решения (если пропустил уведомление).

## 7. Как включить автопубликацию позже

Код для публикации в Threads уже написан и лежит в проекте — просто не
подключён к боту:

- `threads_api.py` — функция `publish_post(text)`, которая публикует текст
  в Threads через Meta Graph API.
- `scheduler.py` — берёт одобренные посты и публикует их по расписанию
  (`POST_TIMES` в `config.env`).
- `scripts/get_threads_token.py` / `refresh_threads_token.py` — получение и
  обновление токенов Threads API (инструкция по получению самих App ID/Secret
  разбирали отдельно — она не изменилась).

Когда решишь включить:
1. Получи `THREADS_USER_ID` и `THREADS_ACCESS_TOKEN` через `scripts/get_threads_token.py`, впиши в `config.env`.
2. В `bot.py` верни `from scheduler import setup_scheduler` и вызов `setup_scheduler(bot, config.ADMIN_USER_ID)` в `main()`.
3. Замени кнопку "✅ Готово" обратно на "✅ Одобрить" со статусом `approved` — тогда `scheduler.py` подхватит пост и опубликует его в ближайший слот расписания.
4. Верни `apscheduler` в `requirements.txt` (сейчас закомментирован).

Могу собрать это обратно в любой момент, когда будешь готов — просто скажи.

## 8. Если YouTube блокирует скачивание

YouTube в 2026 году постоянно меняет протокол стриминга и то, какие
"клиенты" у yt-dlp работают — это открытая гонка между YouTube и
разработчиками yt-dlp, конкретная связка держится неделями, не годами.
Возможные ошибки в логах: `Sign in to confirm you're not a bot`,
`The page needs to be reloaded` и подобные — все они об одном и том же:
YouTube не доверяет запросу с IP хостинга.

**Код уже умеет сам перебирать несколько вариантов клиента** (список
`PLAYER_CLIENT_FALLBACKS` в `downloader.py`) — если один вариант сломался
из-за очередного изменения на стороне YouTube, автоматически пробуется
следующий, прежде чем упасть в ошибку. В логах Bothost будет видно,
какой именно вариант сработал (или что все не сработали).

**Если ошибка всё равно повторяется на ВСЕХ вариантах из списка:**

1. Сначала попробуй просто обновить yt-dlp до самой свежей версии — этот
   баг чинится в yt-dlp быстро, но регулярно всплывает заново на новых
   изменениях YouTube:
   ```bash
   pip install --upgrade yt-dlp
   ```
   и убедись, что `requirements.txt` не ограничивает версию сверху.
2. Если не помогло — добавь в список `PLAYER_CLIENT_FALLBACKS` в
   `downloader.py` ещё вариантов (загугли "yt-dlp player_client 2026" —
   актуальный рабочий вариант часто находится в свежих issues на
   github.com/yt-dlp/yt-dlp).
3. Совсем крайний случай — cookies из своего браузера:
   - Экспортируй cookies из браузера, залогиненного в YouTube. Проще
     всего — расширением типа "Get cookies.txt LOCALLY" (Chrome/Firefox).
     Используй **отдельный** аккаунт Google, не основной — YouTube иногда
     помечает такую автоматизированную сессию как подозрительную и может
     её оборвать.
   - Загрузи получившийся `cookies.txt` на сервер (через файловый
     менеджер Bothost, если он есть — cookies-файл никогда не должен
     лежать в основной ветке репозитория, это по сути пароль от аккаунта).
   - В `config.env` (и в переменных окружения на Bothost) укажи:
     ```
     COOKIES_FILE=cookies.txt
     ```
   - Код сам переключится на использование cookies (клиент `tv`
     автоматически исключается из связки при cookies — их смешивание
     может оборвать сессию в браузере, откуда куки экспортированы).

Учти: cookies периодически протухают (обычно раз в 1-3 месяца) — если
блокировка вернётся после нескольких недель нормальной работы, скорее
всего, дело именно в этом, и cookies нужно экспортировать заново.
блокировка вернётся после нескольких недель нормальной работы, скорее
всего, дело именно в этом, и cookies нужно экспортировать заново.

## 9. Ограничения и что добавить дальше

- **Очень длинные видео** — файлы больше ~95 МБ (это больше часа в 128kbps)
  код сам режет на получасовые куски через ffmpeg и склеивает тексты.
- **Формат ответа kie.ai** — код ожидает поле `text` в результате
  распознавания. Если kie.ai изменит обёртку ответа, `transcriber.py`
  покажет в логе сырой ответ — легко поправить метод `_extract_text`.
- **Ручная подача ссылок** — автопоиска по YouTube пока нет, добавим позже
  через YouTube Data API, когда пайплайн обкатан.
